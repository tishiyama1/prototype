# Forest Action — 3D Diorama + Pixel Characters

比較用の独立版：**[試遊](https://tishiyama1.github.io/prototype/forest-action-diorama-pixel/)** · **[改修前後の比較](https://tishiyama1.github.io/prototype/forest-action-diorama-pixel/comparison.html)**

直近の`forest-action-diorama/`を複製。既存の通常版、全面ピクセル版、ジオラマ版、トップページ、Pages設定は変更しません。ビルド不要のHTML/CSS/ES Modules、three.js 0.180.0を維持。

## 背景：通常解像度の3D

- 幹・枝・根は、曲がり・先細り・根元の広がり・縦の凹凸を持つ共有形状へ変更。円柱の組み合わせによる均一な外形を改善。
- 球体の樹冠を、複数の高さと傾きを持つ葉群へ変更。葉の形・葉脈・隙間を含む高解像度のアルファカットアウトを使用。植生は3D空間で奥行きと遮蔽を持つ。
- 岩を不規則に変形し、丸い摩耗面、ざらつき、苔を追加。石垣の角・石碑の欠けと斑点・蔦を維持し、石材の凹凸を追加。
- 樹皮の凹凸、倒木両端の年輪と割れ、落ち葉や土の自然な色の変化を追加。
- 固定の景観影は初回描画を再利用。小さな木漏れ日の明度変化、少量の粒子と葉の揺れを維持。
- 中央の古道を読みやすく保ち、木・石碑・壁の主配置とカメラは改修前と同じ。

地面・葉には軽いLambert材質、木や石にはStandard材質とバンプマップを使い分けています。背景は低解像度レンダーターゲットや画面全体のピクセル化を使用しません。通常解像度・AAあり、DPR上限1.5。

## キャラクター：専用の2Dドット絵

64×48のセルに、整数ピクセルの輪郭、配色、身体、武器を直接描きます。3Dモデルを撮影・縮小して作った画像ではありません。

- 冒険者：青い服、赤いスカーフ、革の装備、銀の剣。
- 森の剣鬼：緑の肌、尖った耳、紫褐色の服、牙と剣。
- 前・後・左・右の4方向。カメラに面する板に配置し、ターゲットの向きを原画の方向へ対応。
- 最大6フレーム、14状態を用意。接近・回り込み・離脱は移動アニメーションを共用。斬撃・突き・強打は別の構えと振り方。
- NearestFilter、ミップマップなし、二値アルファ。原画の最大色数は21色。
- 地面に固定した接地点、柔らかい接地影、現在の姿勢に追従する投影影。深度判定を有効にし、背景の岩や木で適切に遮蔽される。

描画APIの`archetype`（人間／モンスター）と陣営を分離。各体が独立したフレーム・向き・UV・影を保持し、4体のインスタンスを検査しています。今回は従来の1対1のみで、2対2の操作・AI・カメラ制御は実装していません。

## 剣戟とUI

斬撃・突き・強打の軌跡は専用の少色数ピクセル原画。被弾・ガードは四角い破片で表現します。攻撃予告範囲、攻撃可能距離、HP、4枚の評価カード、総合判定、通常／高速／詳細モード、スキップは維持。

新しいクリティカル抽選やダメージ倍率は追加しません。既存の命中・回避・防御・空振り・割り込み失敗・迎撃に、描画だけを接続します。

## 操作

W/S：接近・離脱、A/D：円弧移動、Shift＋WASD：高速移動、1/2/3：技選択、J：攻撃。iPhone横画面相当はスティック・技ボタン・攻撃ボタン、フィールドのスワイプで回避。カード中はタップ／Spaceで演出短縮。

「静止画」「森を眺める」で景観比較。「調整」では影・霧・環境演出と従来のパラメータを変更できます。通常画面とカードUIの文字は高解像度のままです。

## 検証と制限

`VALIDATION.md`に結果を記録。戦闘・入力・カード・設定・カメラの14モジュールは改修前と同一。

```
node tests/forest-action-diorama-pixel/logic.mjs
node tests/forest-action-diorama-pixel/regression.mjs
```

ブラウザ検査：`browser.cjs`（戦闘・タッチ29項目）、`visual.cjs`（原画・4方向・4体の独立性・遮蔽・画面内収まり・比較）。検査にはPlaywright/Chromiumが必要ですが、ゲームの配信にビルドやnpmインストールは不要です。

iPhone実機Safari、実GPUのFPSは未検証。ソフトウェアGPUの検査では約4FPSで、実機の性能を示す値ではありません。4方向のため向きは段階的に切り替わります。原画の精密さ、方向数、実機での描画速度は今後の改善候補です。
