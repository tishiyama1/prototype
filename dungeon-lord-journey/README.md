# ダンジョンの主 — 旅・探索・仕事プロトタイプ

比較用エントリーポイント：`dungeon-lord-journey/`。

既存の `forest-action-frontline/` を変更せず、戦闘を `battle/` に専用コピーして連携しています。コピー元：`e1b41e217bcd0cf7689a65b8acf986d5e83b3f65`。背景素材は既存の森・洞窟の素材を参照します。ルートのメニューや既存公開パスは変更しません。

## 遊び方

地図で場所を選び、探索するか、その場所の仕事を選びます。移動は行動に含まれます。1週間は前半・後半の2回行動。行動の結果を確定してから半週を進めます。週の最後の場所で夜を明かし、主が見張ります。

初めは街の外れしか知りません。門の外を探索すると農村への道と鉱山の噂を知ります。探索では地域ごとの固定パターンで0〜2戦、護衛や発展後の危険な採掘では1戦が発生します。ランダム抽選による地域イベントはありません。

食料は行動ごとに1消費。仕事や農村の探索で補充できます。食料0・衛生20未満は仕事報酬が各1G減るだけで、行動不能や期限切れにはなりません。街へ入れる大きさになった後、街の外れで過ごすと衛生が回復します。行商人の買い物は持ち物画面にあり、時間は消費しません。

主の能力を渡す操作はありません。各地の人を訪ね、仕事をしているうちに主が自分で渡します。一度渡した能力はもう一方には渡せません。譲渡から2週後と4週後に地域が段階的に発展し、新しい仕事や品物が増えます。主は3.0mから1.8mになり、王の剣を失って魔法弾に変わります。

手帳は聞いた情報を保存する場所です。能力譲渡の判定条件やエンディング条件を画面へ出しません。

## 構造

| ファイル | 担当 |
| --- | --- |
| `js/data.js` | 地域、仕事、噂、武器・衣服、イベント条件と効果 |
| `js/engine.js` | 純粋な旅の状態遷移、半週進行、結果確定、保存の検証 |
| `js/app.js` | 地図、イベント、仕事、手帳、持ち物、設定、戦闘iframeの仲介 |
| `battle/js/journey-context.js` | 旅から渡す能力・サイズ・装備・熟練度と、威力係数 |
| `battle/js/journey-bridge.js` | 実際の戦闘結果を親画面へ返す |
| `tests/dungeon-lord-journey/` | 状態・分岐・戦闘ロジック、ブラウザ操作の検証 |

旅の状態はschema 1のJSONです。週・前後半・現在地・生活3値・地域の発見／訪問／変更版・イベント完了履歴・行動履歴・宿泊履歴・世界状態・主の能力・装備と熟練度・手帳を持ちます。

イベントの `when` は現在地、行動種類、仕事、完了履歴、訪問回数、経過週、能力、世界状態、行動順序、譲渡からの週数を評価します。`effects` は地域／仕事／噂の開放、品物／武器の取得、フラグ、地域状態、主の能力譲渡を適用します。完了済みイベントは再実行しません。

行動は `before event → battle(s) → after event → map` の順です。探索や仕事を二重に開始できません。戦闘結果はアクティブなiframe、同一origin、現在の遭遇IDで検証し、重複を無視します。途中の戦闘勝利による素材・熟練度は保存しますが、行動の時間・仕事報酬は全戦闘が終わってから確定します。敗北すると主が身代わりになって旅もゲームオーバー。明示的な「出発前からやり直す」で行動前のチェックポイントへ戻せます。

## 戦闘と5要素

直接戦うのは前衛2体のみ。後衛は自分側の前衛の後ろを追従します。敵後衛の予兆弾、主の遠距離援護、敵前衛撃破後の後衛逃走、主人公への致命傷に対する主の死亡を継承します。

攻防判定の順序・間合い・隙・移動境界・敵AIは既存のコードを保っています。カードは既に確定した攻撃を説明する5要素で、選択式カードバトルではありません。

1. 間合い：届く距離と踏み込み。
2. 隙：敵の硬直や攻撃の先着。
3. 体勢：停止して安定／移動中90%／回避直後82%／被弾後72%の威力係数。
4. 環境：武器・外套・靴の全3部位について場所との適性を評価。威力係数0.94〜1.06。
5. 攻撃手段：武器・技の性能と使用時の熟練度。

主人公HPは常に100でレベル制はありません。戦闘で使った技に最大3ずつ熟練度を付与し、使用武器にも同数を加算します。熟練度6／16で段階が上がり、武器は各段階8%、技は各段階4%の威力補正が付きます。間合い・隙の判定条件を緩める処理はありません。旅の剣、鉱山のつるはしの2種類を代表例としています。

## 保存と通信

旅専用localStorageキー `dungeon-lord-journey:v1` を使います。既存作品の保存キーには触れません。戦闘入力はsessionStorageの遭遇ID付き一時データです。戦闘中にページを閉じた場合は現在の遭遇の開始から再開し、終了済みの遭遇を重複加算しません。

読めない保存は自動で捨てず、案内を出します。ユーザーが新しい旅を始めた場合は読めなかった内容を `:unreadable` の控えへ残します。保存不可の場合は画面に表示してメモリ上で進めます。

戦闘のthree.jsはCDN依存です。読み込みを妨げる環境では旅を進めても戦闘へ入れません。戦闘開始から30秒後に再読み込みの導線を出します。完全オフラインやiOSネイティブ化は今回行っていません。

## 検証

```sh
node tests/dungeon-lord-journey/logic.mjs
node tests/dungeon-lord-journey/browser.cjs
```

ブラウザ検証にはPlaywrightとChromiumが必要です。`FOREST_ENV_BASE` で公開URL、`FOREST_QA_OUTPUT` で画像・結果の保存先を指定できます。ローカル実行時は既存と同じ小さなHTTPハーネスを使います。

検証機能の表示はURLに `debug=1` を付けた設定画面だけです。通常UIに判定条件や状態変更ボタンを出していません。

## 範囲と既知の限界

3地域と1種類の能力譲渡を使った短い試作です。発展後の新しい発見はまだ少なく、旅を長く続けるためのコンテンツ量はありません。本格エンディング、動物への能力譲渡、追加地域、装備や技の大量追加、クラウド保存は未実装です。

戦闘の難易度や報酬数値は仮です。再読み込みで現在の戦闘をやり直せます。セーブの改変を防ぐ仕組みはありません。iPhone実機Safari、実機FPS・発熱、長時間プレイの楽しさは未評価です。
